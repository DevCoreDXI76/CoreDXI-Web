## 5. 실행 지침 (Guidelines)

### 5-1. 문서·계획 관리
- 모든 계획 변경은 `docs/PRD.md`(요구사항)와 `docs/TODO.md`(구현 현황)에 **먼저 반영**한 뒤 개발 착수 — 기존 프로젝트 관행을 그대로 준수
- 새 기능은 착수 전 `docs/superpowers/specs/`에 설계 문서를 남기는 기존 패턴(CSP 설계 문서 사례)을 따를 것

### 5-2. 개발 규칙
- 커밋 메시지는 Conventional Commits(`feat:`, `fix:`, `refactor:`, `chore:`, `docs:`) 형식 유지 — post-commit 훅이 Notion Tasks에 자동 기록
- `prisma migrate dev`는 사용 금지 — `contacts`/`contact_settings`(Supabase 직접 생성 테이블)와 충돌하여 스키마 리셋 위험. 반드시 수동 `migration.sql` + `prisma migrate deploy`
- `@tiptap/*` 버전은 `3.13.0`으로 고정(`overrides`) — 업그레이드 시 전체 회귀 테스트 필수
- 신규 기능도 기존 테스트 스택(Vitest 유닛 + Playwright E2E 골든패스) 커버리지 유지

### 5-3. 디자인·콘텐츠 가이드
- 브랜드 컬러(로열 블루 `#1E4E8C`), 코너 반경 `0.75rem` 이상, 여백 중심의 미니멀 톤앤매너 유지 (채널톡·Loom 참조 철학)
- 신규 UI는 shadcn/ui 컴포넌트 우선 사용, WCAG AA 대비 기준 검증(다크모드 작업 시 이미 검증한 패턴 재사용)
- 콘텐츠 수정은 `CONTENT_GUIDE.md`를 최신화하며 진행 — 홍보팀이 코드 없이 편집 가능한 범위를 넓히는 것이 이번 프로젝트의 핵심이므로, 신규 CMS 기능 추가 시마다 가이드 문서도 함께 갱신

### 5-4. 보안·품질
- 신규 폼(뉴스레터 구독, 예약 시스템 등)에는 기존 rate limiting 패턴(`RateLimitHit` 테이블 기반) 재사용
- 외부 서비스 연동(Calendly, Resend Audiences 등) 시 SSRF·CORS 정책은 기존 `src/lib/url-safety.ts` 패턴을 참고해 신규 코드에도 동일 적용
- Sentry 트레이스 샘플링(20%) 및 CSP nonce 정책은 신규 라우트 추가 시에도 예외 없이 적용

### 5-5. 역할 분담 제안
| 역할 | 담당 | 책임 |
|------|------|------|
| 프로젝트 오너 | 경영진/마케팅 리드 | 목표·KPI 승인, 우선순위 최종 결정 |
| 콘텐츠 기획 | 홍보팀 | 뉴스레터/블로그/회원 전용 콘텐츠 기획, CONTENT_GUIDE.md 갱신 |
| 개발팀 | 개발팀 | Phase별 기능 구현, 테스트, 배포, `docs/` 갱신 |
| QA/보안 | 개발팀 또는 외부 검수 | CSP 전환 검증, 신규 폼 보안 점검, 접근성 검증 |

## 6. 리스크 및 열린 질문

- **CMS 구조 편집 확장(Phase 2-#5)**: PRD에 "재설계 필요"로 명시된 항목으로, 다른 기능 대비 개발 공수가 큼 — 별도 스펙 문서 선행 필요
- **다국어 지원**: 도메인 전략(서브도메인 vs 서브패스), 콘텐츠 번역 리소스(자체 번역 vs 외주) 결정 필요
- **예약 시스템**: Calendly 연동(빠름, 커스터마이징 제한) vs 자체 구현(느림, 데이터 소유) 트레이드오프 결정 필요
- **Notion 연동 확장 여부**: 세일즈 CRM 연계 필요성이 실제로 있는지 영업팀 확인 필요
- **엔지니어링 속도가 시장 접촉을 앞지르는 리스크 (2026-09-06 확인됨)**: Phase 1.5 자동 팔로업(C단계)이 계획보다 열흘 빨리 완료된 반면 첫 링크 발송은 0건 — 트랙의 가장 위험한 가정("대표가 카톡으로 받은 3분 진단을 실제로 한다")이 2주째 미검증. 대응: 첫 발송 마감 09/11 고정 + 09/10 미발송 시 사용자 직접 발송, 실응답 5건 + HOT 1건 전까지 신규 기능 착수 동결
- **계획 문서 다층화로 인한 드리프트**: CLAUDE.md·PRD·TODO·기획서·액션플랜·노션·프로젝트 메모리가 같은 서사를 각자 보유 → 역할 고정(PRD=요구사항, TODO=구현 현황, 노션=액션·일정, 경위 서사는 액션플랜에만)하고 단계 전환 시점마다 정합화 세션을 둔다
- **콘텐츠 소싱 프로세스 부재 (2026-08-14 실현됨)**: "블로그 이탈률 감소" 같은 KPI(3번)를 추적할 콘텐츠 자체가 검증 안 된 프로세스로 만들어져 저작권 리스크로 전량 삭제되는 사건이 발생 — 재발 방지책은 `CONTENT_GUIDE.md` 16번에 명문화 완료(7번 부록 참고). 향후 콘텐츠 관련 KPI는 재건 완료 전까지 기준선(baseline)이 사실상 없다는 점을 감안해 해석할 것

## 7-B. 부록 — 영업 지원 트랙 신설 (2026-08-22)

영업이사(비등기 임원) 합류를 계기로 홈페이지의 역할에 "영업이사 아웃바운드 지원"을 추가했다. 브레인스토밍에서 합의한 판단은 다음과 같다.

- 영업이사가 보내는 링크는 `/ax-check`이지 회사 소개가 아니다 → 회사 소개·솔루션 개편은 2단계로 미루고, 질문지 깔때기를 2주 내(09/05) 먼저 연다
- 가장 위험한 가정은 "대표가 카톡으로 받은 설문을 끝까지 채운다"이다 → 8문항·3분·전부 선택지, 문항 7·8을 리드 등급(Timing·Authority) 판정에 겸용
- 1단계 AI 분석은 규칙 기반 요약으로 대체하고, 응답 20건 누적 후 LLM을 "관리자 검토 후 발송"으로 붙인다
- 뉴스레터 발송은 "접촉 리드 팔로업 월 1회"로 목적을 좁혀 다시 연다 — 담당자 확정이 선행 조건
- 타깃 업종은 IT·통신·AV 시스템 구축 업체로 좁히고, 건설업(동진기술 유형)은 향후 추가 후보로만 둔다

## 7-C. 부록 — 전체 방향 재검토 (2026-09-06)

헌장·PRD·TODO·기획서·액션플랜 재독과 git·노션 재조회를 거친 브리핑 후 사용자가 결정한 사항.

- **진단**: Phase 1은 계획대로 종료됐고 Phase 1.5의 기술은 계획을 앞서 있으나, 실응답은 0건이라 "완료율 점검(09/08)"부터 3단계까지 전부 데이터 없이 대기 중. 유기 퍼널(30일 문의 0건)은 기준선이 없어 8/3 KPI로는 성과를 잴 수 없음
- **결정 ①**: 영업이사 첫 링크 발송 마감을 이번 주(09/11 금)로 고정. 09/10까지 발송이 없으면 사용자가 지인 채널 2~3곳에 직접 링크를 보내 첫 데이터를 만든다
- **결정 ②**: 뉴스레터·콘텐츠 발송 담당(0-7)은 사용자 본인 + AI 비서로 확정(시스템 자동 발송 + 사용자 승인, A-5 결정과 정합)
- **결정 ③**: Phase 2를 "영업 도구 고도화"로 재정의(4번 참고). 3번 목표표도 3-B로 재정의
- **운영 원칙**: 실응답 5건 + HOT 1건 확보 전까지 신규 기능(E 2차·LLM·Calendly·Broadcasts) 착수 동결. 콘텐츠는 영업에서 소재를 받아오는 구조(인터뷰 Q&A → FAQ·블로그, 응답 통계 → 다음 글)로 운영
- **후속**: 노션 액션 DB 5건 갱신(1-11 날짜 09/11, 3단계 날짜 09/29~10/31 이월, 2단계·E 2차 메모에 게이트 기록), PRD·TODO·CLAUDE.md 정합화

## 7. 부록 — 콘텐츠 전략 갱신 (2026-08-14)

Phase 1 마지막 잔여 항목(전환 퍼널 대시보드 2단계) 착수를 앞두고, coredxi.com 블로그 게시물
다수가 외부 콘텐츠를 복사·붙여넣기한 것으로 확인되어 전체 삭제하는 사건이 있었다. 이를 계기로
콘텐츠 마케팅 목표(위 3번 표)의 실행 전략을 다음과 같이 구체화했다.

- **브랜드 구조**: 사용자가 별도 운영 중인 개인 브랜드("피프티바이브")와 CoreDXI 법인 브랜드는
  분리 정체성을 유지하되, 이미 검증된 콘텐츠 리서치 파이프라인의 AI/Claude 생산성 클러스터만
  CoreDXI 톤으로 재가공해 blog에 반영하는 "선택적 콘텐츠 브릿지" 모델을 채택
- **리드 채널**: 지인 소개·네트워킹(신뢰 확인형)과 크몽·숨고 리스팅+팔로워 문의(발견·전환형)
  두 채널 모두를 서비스하는 것으로 확인 — 동일 역량(AI/AX 컨설팅)을 규모만 다르게 판매
- **재발 방지**: `CONTENT_GUIDE.md`에 콘텐츠 소싱 정책(복붙 금지, 원본 리서치 또는 검증된
  파이프라인 경유 원칙) 명문화
